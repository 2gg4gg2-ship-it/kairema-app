## 2. Что за проект

Kairema это ИИ-чат для Android. Пользователь вставляет **свой** API-ключ любого OpenAI-совместимого провайдера (OpenRouter, OpenAI и другие) или Anthropic и общается с моделями. Остальное:

- история чатов (закрепление, переименование, удаление), умный поиск по чатам, сообщениям и блокам кода;
- память (профиль и факты о пользователе; факты находятся автоматически, в запрос к ИИ уходят подобранные под вопрос; подробности в разделе 4, «Память»);
- поиск в интернете (Tavily, Brave, Serper, ключи пользователя) и режим «Глубокое исследование» (несколько поисков и отчёт с источниками);
- создание изображений, режимы «Думать» (Thinking) и «Быстрый ответ» (Instant);
- терминал: оболочка Android и Termux, ИИ предлагает команды, пользователь подтверждает кнопкой «Выполнить», есть режим агента (до 8 шагов);
- вложения (фото, текст, PDF), файлы из ответов ИИ (таблицы, HTML, CSV, PDF), «Поделиться», сохранение чата как PDF;
- счётчик токенов и примерной стоимости;
- вход по почте и облачная синхронизация чатов и памяти через Supabase.

Распространяется APK по прямым ссылкам, не через магазин. Решение владельца: друзей, карты и мессенджера в приложении **не будет**.

## 3. Репозиторий, язык, стек

- Репозиторий: `https://github.com/2gg4gg2-ship-it/kairema-app` (ветка `main`, публичный).
- Приложение нативное: **Kotlin** (одна Activity) + **WebView**, внутри которого интерфейс на **HTML, CSS и чистом JavaScript** без сборщика, без npm-зависимостей, без CDN и без фреймворков.
- minSdk 26, targetSdk 34, compileSdk 34, Android Gradle Plugin 8.5.2, Kotlin 2.0.20, OkHttp 4.12.0, org.json. Без AndroidX и Compose (только если очень нужно и ты объяснил владельцу зачем).
- `applicationId` = `com.kairema.app`. **Не меняй** его, а также `app/debug.keystore`: иначе новые APK перестанут ставиться поверх старых.

Какой язык для чего:

| Задача | Чем делать |
|---|---|
| Экраны, логика интерфейса, данные пользователя | JavaScript в `app/src/main/assets/ui/features/<имя>/` |
| Вид, анимации, цвета | CSS в папке модуля; общие токены и базовые стили в `core/styles.css` |
| Доступ к Android: файлы, Intents, процессы, разрешения, базы, службы | Kotlin в `app/src/main/java/com/kairema/app/<имя>/` |
| HTTP к ИИ-провайдерам и поиску | Kotlin (OkHttp). Ключ берётся из Keystore и **не попадает в JS** |
| HTTP к Supabase (вход, синхронизация) | JavaScript `fetch` (публичный anon-ключ не секрет) |
| Права доступа к облачной базе | SQL в `features/<имя>/schema.sql`, владелец сам выполняет в Supabase |

Направление развития: **тяжёлое и системное переносим на Kotlin** (хранилище, сеть, файлы, фоновые задачи), а **визуал и быстрые эксперименты оставляем на JS/CSS/HTML**.

```
.github/workflows/build.yml   сборка debug APK и распаковка обновлений (НЕ трогай и НЕ клади в zip)
settings.gradle.kts
app/build.gradle.kts          версия (versionCode, versionName), зависимости
app/src/main/
  AndroidManifest.xml         разрешения, <queries>, activity, службы, провайдер файлов
  assets/ui/
    index.html                ПОРЯДОК подключения модулей (css и js)
    core/                     app.js (экраны, чат, respond), styles.css (токены дизайна), hooks.js, config.js (APP_VERSION)
    features/<имя>/           модуль: свои .js и .css (и .sql). Одна функция = одна папка
  java/com/kairema/app/
    MainActivity.kt           окно, WebView, «Назад», выбор файлов, результаты разрешений
    bridge/Bridge.kt          мост JS <-> Kotlin: чат/потоки, картинки, поиск, модели, проверка ключа, терминал, share
    data/                     SecureKeys (Keystore), ChatDb и DbBridge (SQLite и файлы вложений)
    service/KeepAliveService  служба переднего плана на время длинных задач
    search/                   WebRelevance (очистка веб-запроса), SearchIndex и SearchBridge (FTS5 по чатам)
    system/SystemBridge       «на весь экран», размеры панелей, клавиатура, тема
    terminal/, share/         оболочка и Termux, буфер обмена, «Поделиться», печать в PDF
```

Модули интерфейса (`features/`): `markdown`, `chats`, `providers` (обязательные, ядро зовёт их напрямую); необязательные: `inbox`, `backup`, `about`, `share`, `artifacts`, `auth`, `memory`, `sync`, `terminal`, `scroller`, `search`, `brand`, `system`, `tools`, `caps`, `cost`, `help` (справка: тексты в `help-data.js`, обновляй при смене функций). Удаление необязательного модуля (папка и его строки в `index.html`) не должно ломать приложение.

### Правила подключения модуля, не правя `core/app.js`
- Модули загружаются **до** `core/app.js`. Поэтому на верхнем уровне модуль не должен трогать глобальные переменные и функции из `app.js` (например `P`, `S`). Всё, что их использует, делай внутри обработчиков.
- События: `Hooks.on('app:ready', fn)`, `Hooks.on('settings:rendered', fn(el))`, `msg:render(d,m)`, `chat:rendered`, `chat:answer(m, bd)`, `md:code`, `md:table`, `memory:changed`, `sync:touch|delete|register`, `account:rendered`. Новые события описывай в шапке `core/hooks.js`.
- Экран: `SCREENS.<имя> = функция`, открывается `openScreen('<имя>')`; вспомогательная `page(имя, заголовок, render(b,d))`.
- Переводы: `i18nAdd({"Русский текст":"English text"})`. **Ключ перевода это русский текст.** Меняешь русскую строку, обнови английскую.
- Новое: нативный код в своём пакете; в `Bridge.kt` только тонкие методы-делегаты.

### Мост JS <-> Kotlin
- Интерфейсы WebView: `KairemaBridge` (Bridge), `KairemaSysBridge`, `KairemaDb`, `KairemaSearch`.
- Длинные операции асинхронны: JS `Native.run(метод, [аргументы], onChunk)`, Kotlin отвечает `KairemaNative.chunk(reqId, текст)` и `KairemaNative.done(reqId, ошибкаИлиNull)`. Отмена `Native.cancel(id)`. Короткие синхронные: `Native.sync(метод, ...args)` (вызывает только `KairemaBridge`).
- Кодировка кусков потока: текст рассуждений модели начинается с `\u0001`; данные расхода (`{i,o,c}`) с `\u0002`; результат картинки приходит JSON `{mime,b64}`.
- `Native.on` равно false в обычном браузере: тогда работает демо-режим (удобно для тестов).
- Kotlin вызывает JS через `evaluateJavascript` (например `Sys.insets(верх,низ,клавиатура)`).

### Память (0.25, `features/memory`)
- Факт: `S.memos[i] = [текст, источник, id, время, meta]`, `meta = {c: категория, p: закреплён, a: найден автоматически, u: сколько раз ушёл модели, l: когда}`. Категории: identity, work, prefs, interests, people, goals, tech, other. Профиль пользователя: `S.prof` (хранится в `kairema.memory.v1`, синхронизируется элементом `_profile`).
- `memory.js`: хранилище, `Mem.add/update/remove/setMeta`, защита от дублей (`dupOf`, сравнение по основам слов) и секретов (`Mem.SECRET`), быстрые правила `Mem.local` («меня зовут», «я живу в», «запомни…»), подбор `Mem.pick(вопрос)` и подсказка `Mem.prompt()` (профиль всегда, закреплённые и «личное» всегда, подходящие по словам, несколько последних; ≤20 фактов уходят все; до ~1800 символов). `memoryPrompt()` вызывается из `sysPrompt()`.
- `memory-ai.js` (`Mem.ai`): после ответа (`chat:answer`) в фоне один короткий запрос тому же провайдеру, модель возвращает JSON `{ops:[add|update|delete]}`; удаление только если пользователь сам попросил «забудь»; отмена кнопкой «🧠 N» под ответом; `Mem.ai.scan()` разбирает старые чаты. Токены этих запросов в «Расходы» пока не входят.
- `memory-ui.js`: экран «Память» (подменяет `SCREENS.memory`), метка «🧠 N» под ответом показывает, какие факты ушли модели.
- Не меняй формат `toItem/fromItem` без миграции: он идёт в Supabase и в резервную копию.

### Данные
- Чаты в SQLite (`kairema.db`, одна строка = чат), картинки и вложения файлами в `filesDir/media`, в чате только имя файла. Режим выбирается `Chx.db()`. В браузере и тестах запасной режим localStorage. Не возвращай чаты в localStorage.
- Остальное в localStorage: `kairema.<что>.v1` (провайдеры `kairema.providers.v1`, статистика `kairema.usage.v1`, тарифы `kairema.prices.v1`, возможности моделей `kairema.mcaps.v1`). Меняешь формат: создай `.v2` и мигрируй.
- Индекс поиска `kairema_search.db` (FTS5, запасной режим LIKE).
- Ключи ИИ и поиска: только Android Keystore (`SecureKeys.kt`), в JS не попадают.

В `docs/NOTES.md` запиши, что берёшь.

4. **Меняй минимум.** Точечные замены с проверкой числа совпадений (assert count == 1). Работающее не ломай. Новая возможность идёт новым модулем. В общих файлах (`core/app.js`, `core/styles.css`, `index.html`, `hooks.js`) только точечные правки, и записывай их в `docs/NOTES.md`.

После сборки архива проверь `unzip -l kairema.zip | grep settings.gradle.kts`. **Никогда не клади `.github/`**: токен автоматической сборки не имеет права менять workflows. Отправь файл владельцу и коротко опиши: что сделано, что не проверено, что делать дальше.

## 6. Как сборка и выкладка работают у владельца

1. Владелец открывает репозиторий на GitHub: Add file, Upload files, загружает `kairema.zip` в корень, Commit changes.
2. Workflow находит `.zip` в последнем коммите, удаляет `app/` и `settings.gradle.kts`, распаковывает архив поверх, коммитит от имени github-actions и собирает debug APK (JDK 17, Gradle 8.9, `assembleDebug`). Артефакт `kairema-debug-apk`.
3. Владелец скачивает артефакт в Actions и ставит `app-debug.apk` поверх старого.
4. Если сборка красная, он присылает скриншот шага. **Ты не можешь собрать приложение и скомпилировать Kotlin**, поэтому ошибки Kotlin ловит только CI. Относись к Kotlin как к коду без компилятора.

## 7. Как проверять без телефона

- JavaScript: `node --check`.
- Интерфейс: Playwright (Chromium) или jsdom. Грузится `app/src/main/assets/ui/index.html`, мосты подменяются заглушками **до загрузки страницы** (init-скрипт, только в главном окне `window===window.top`). Что обычно подменяют: `localStorage` ключи `ko` и `kna` (пропускают онбординг и заставку), `kairema.providers.v1` (формат `{c:[{id,name,model,url,ok}], s:[провайдеры поиска]}`), `window.KairemaBridge` (`saveKey`, `hasKey`, `cancel`, `chat(id,prov,msgs)` с вызовом `KairemaNative.chunk/done`), `KairemaSysBridge` (`dark`, `bars`), по необходимости `KairemaDb`. Подожди ~5,8 с после загрузки, пока пройдёт заставка. Делай скриншоты (viewport 360x780) и смотри на них.
- В `docs/tests/` лежат тесты jsdom (вход, синхронизация, терминал, поиск). Запуск описан в `docs/tests/README.md`.
- На каждую новую возможность добавляй проверку. Честно пиши, что проверено в браузере, а что нет на реальном телефоне.

## 8. Kotlin без компилятора: что проверять и на чём уже спотыкались

- Дубли имён локальных переменных в одной функции (**сборка 0.18.0 упала из-за двух `val pr`**). Перед вставкой кода перечитай всю функцию.
- Импорты, типы, `null`-безопасность, `val`/`var`, возвраты из лямбд (`return@runOnUiThread`).
- SAM-лямбды: пиши `Runnable { }` явно в `Handler.postDelayed`.
- Версии API (minSdk 26): `ServiceInfo.FOREGROUND_SERVICE_TYPE_DATA_SYNC` только с API 29, `startForegroundService` с 26, на Android 13+ нужен запрос `POST_NOTIFICATIONS`, на 14 нужны разрешения типа службы.
- Коды запросов разрешений и результатов не должны совпадать (`REQ_FILE=1`, `REQ_MEDIA=7103`, `REQ_NOTIFY=7105`; 7102 и 7104 были у удалённого голосового ввода).
- `@JavascriptInterface`-методы публичные и принимают простые типы.
- Android 11+: чтобы видеть чужие службы и пакеты, нужны записи в `<queries>` (сейчас только Termux).
- WebView рисует постер видео (серый квадрат с play) до первого кадра: у `WebChromeClient` переопределён `getDefaultVideoPoster()`.
- Из папки данных приложения Android 10+ нельзя запускать файлы; `startService` в Termux из фона отклоняется (резерв `startForegroundService`); разрешение `RUN_COMMAND` на некоторых прошивках запрашивается только окном из приложения.
- WebView не поддерживает `getDisplayMedia` и веб-распознавание речи: делается нативно.
- `http://` адреса блокируются (cleartext отключён).

## 9. Безопасность (не обсуждается)

- API-ключ **никогда** не попадает в JavaScript, логи и промпты. JS передаёт только id провайдера.
- Ключи поиска уходят только на фиксированные адреса Tavily, Brave и Serper.
- Чужой текст (ответ модели, результаты поиска, файлы) выводится через `textContent` или `mdRender`, не через `innerHTML`. Ссылки только http(s).
- Команды терминала от ИИ выполняются **только после подтверждения владельца**; опасные помечаются и в автоматическом режиме агента не запускаются. Помни про prompt injection: текст из интернета и файлов может подсказывать модели вредные команды.
- Геопозиция и подобное только с явного согласия.
- В репозиторий не кладутся секреты. Исключение: `app/debug.keystore` (пароль `android`) только для debug-сборок.
- Публичный anon-ключ Supabase безопасен только при включённом RLS; секретный ключ (`sb_secret_`) в приложение не вставляй.

## 12. Чего не делать

- Не затирать чужую работу и не выдавать архив от устаревшей базы.
- Не класть `.github/` в архив. Не менять `applicationId`, `debug.keystore`.
- Не переписывать файлы целиком без необходимости, не ломать работающее.
- Не добавлять библиотеки, CDN, npm-пакеты без веской причины.
- Не говорить «исправлено», если не проверил. Если не можешь проверить на телефоне, так и пиши.
- Не просить владельца запускать команды на компьютере: у него только телефон.
