# Руководство для Claude (и любых других ассистентов), которые работают над Kairema

Прочитай целиком перед любой работой. Этот файл живёт в репозитории и обновляется вместе с проектом.
Дополнительно читай `README.md` (структура и возможности) и `docs/NOTES.md` (что сейчас в работе, что осталось).

## 0. Кто мы и как работаем

- Владелец проекта работает **только с телефона** (iQOO, Android 16), компьютера нет. Он присылает скриншоты.
- Отвечай **по-русски**, простыми словами, короткими предложениями. Давай **один шаг за раз** и жди ответ или скриншот.
  Не больше одного вопроса за сообщение. Не печатай в чат целые файлы кода: экран телефона вмещает 6-8 предложений.
- Все инструкции должны выполняться нажатиями в мобильном Chrome и на сайте GitHub. Названия кнопок GitHub пиши по-английски, как их показывает GitHub.
- Ты не можешь собрать приложение и не можешь скомпилировать Kotlin. Поэтому Kotlin пиши и перечитывай особенно внимательно (см. раздел 6).
- Бюджет сейчас нулевой: только бесплатные тарифы. Ключи ИИ и поиска у каждого пользователя свои (BYOK).
- Рядом работают и другие Claude. Главная цель правил ниже: **не затирать работу друг друга и не ломать работающее**.

## 1. Золотые правила

1. **Начинай с актуального репозитория.** `git clone https://github.com/2gg4gg2-ship-it/kairema-app` (ветка main, репозиторий публичный).
   Репозиторий это источник правды. Не опирайся на память, старый zip или прошлый чат.
   Если сети нет, попроси владельца прислать ZIP репозитория (GitHub: Code, Download ZIP).
2. **Читай:** `README.md`, этот файл, `docs/NOTES.md`. Запиши в `docs/NOTES.md`, что берёшь задачу («Сейчас в работе»).
3. **Меняй минимум.** Точечные замены строк с проверкой числа совпадений (assert count == 1). Не переписывай файлы целиком без необходимости.
   Работающие функции не ломай. Новая возможность идёт новым файлом в нужной папке (раздел 3).
4. **Проверяй.** `node --check` для каждого изменённого .js. Запусти тесты из `docs/tests` (раздел 5). Kotlin перечитай дважды.
5. **Версия.** `versionCode` = значение в свежем репозитории + 1. Обнови `versionName` (0.x.y) в `app/build.gradle.kts`,
   строку «Текущая версия» в `README.md`, константу `APP_VERSION` в `app/src/main/assets/ui/core/config.js`.
   Добавь строку в `docs/CHANGELOG.md`. Иначе GitHub посчитает загрузку «без изменений».
6. **Перед выдачей zip снова скачай свежий репозиторий** и сравни с тем, от чего ты начинал. Если за время работы он изменился
   (другой Claude успел выложить версию), **перенеси свои правки на свежую версию** и подними номер версии выше. Никогда не выдавай zip, собранный от устаревшей базы: загрузка заменяет всю папку `app/`.
7. **Доставка.** Один файл `kairema.zip` с содержимым: `.gitignore`, `README.md`, `settings.gradle.kts`, папка `app/`, папка `docs/`.
   **Никогда не кладёшь `.github/`**: автоматический токен не имеет права менять workflows. Не клади в zip лишнее.
8. **После выдачи обнови `docs/NOTES.md`:** что сделано, что осталось, что нужно проверить владельцу.
9. **Безопасность** (раздел 7) важнее скорости.
10. **Не меняй** `applicationId` (com.kairema.app), `app/debug.keystore` и подпись: иначе новые APK перестанут ставиться поверх старых.

## 2. Что за приложение

Android-приложение Kairema: ИИ-чат, где пользователь подключает **свой** ключ (BYOK) к любому OpenAI-совместимому API
или Anthropic. Есть история чатов, память, поиск в интернете (Tavily, Brave, Serper), терминал (оболочка Android и Termux),
вход и облачная синхронизация (Supabase), «поделиться», файлы из ответов ИИ (таблицы, HTML, CSV, PDF).
Распространяется APK по прямым ссылкам, не через магазин. Друзей, карты и мессенджера **не будет** (решение владельца).

Стек: нативный Kotlin с одной Activity и WebView (интерфейс на HTML/CSS/JS), minSdk 26, targetSdk 34, compileSdk 34,
Android Gradle Plugin 8.5.2, Kotlin 2.0.20, OkHttp 4.12.0, org.json. Без AndroidX, без Compose (пока).

## 3. Архитектура: где что лежит

```
app/src/main/
  AndroidManifest.xml          разрешения, activity, receiver
  assets/ui/                   интерфейс (WebView)
    index.html                 точка входа: ПОРЯДОК подключения модулей (css и js)
    core/                      ядро: app.js (экраны и общие функции), styles.css (дизайн-токены), hooks.js, config.js
    features/<имя>/            модуль: свои .js и .css (и .sql). Одна функция = одна папка
  java/com/kairema/app/
    MainActivity.kt            окно, WebView, «Назад», выбор файлов
    bridge/Bridge.kt           мост JS <-> Kotlin (методы с @JavascriptInterface)
    <имя>/                     нативный код модуля в своём пакете (terminal, share, data)
```

**Слои не смешиваются:** интерфейс только в `assets/ui`, нативный код только в `java`. Новая возможность = новая папка в нужном слое.

### Обязательные и необязательные модули
- Обязательные (ядро вызывает их напрямую): `markdown`, `chats`, `providers`.
- Необязательные (подключаются через Hooks; удаление папки и строк в `index.html` не ломает приложение):
  `about`, `share`, `artifacts` (нужен share), `auth`, `memory`, `sync`, `terminal`, `scroller`, `voice` (нужен Kotlin `voice/`), `brand`, `system` (нужен Kotlin `system/`).

### Как подключается модуль (не правя `core/app.js`)
- `Hooks.on('app:ready', fn)`: приложение запущено. `Hooks.on('settings:rendered', fn(el))`: экран настроек нарисован.
  Другие события: `md:code(pre, code, lang)` (блок кода в ответе ИИ), `chat:answer(m, bd)` (ответ ИИ показан),
  `memory:changed`, `sync:touch(kind,id)` / `sync:delete(kind,id)` / `sync:register(Sync)`, `account:rendered`.
  Свои события добавляй и **описывай в шапке `core/hooks.js`**.
- Экран: `SCREENS.<имя> = функция` (после `app:ready`). Открывается `openScreen('<имя>')`.
- Переводы: `i18nAdd({"Русский текст":"English text"})`. **Ключ перевода это русский текст.** Изменил русскую строку, обнови английскую.
- Строки модулей перечислены в `index.html` между комментариями «МОДУЛИ»; порядок важен: модуль должен загружаться **до** `core/app.js`.
- Данные в localStorage: ключи вида `kairema.<что>.v1`. Меняешь формат: создай `.v2` и перенеси данные (миграция), старое не удаляй сразу.

### Мост JS <-> Kotlin
- Kotlin объявляет методы в `Bridge.kt` (`@JavascriptInterface`). Длинные операции асинхронны: JS вызывает `Native.run(метод, [аргументы], onChunk)`,
  Kotlin отвечает `KairemaNative.chunk(reqId, текст)` и `KairemaNative.done(reqId, ошибкаИлиNull)`. Отмена: `Native.cancel(id)`.
  Синхронные короткие вызовы: `Native.sync(метод, ...аргументы)`.
- `Native.on` равно false в обычном браузере: тогда работает демо-режим (нужно для тестов).
- Новый нативный модуль: отдельный класс в своём пакете, в `Bridge.kt` только тонкие методы-делегаты.

## 4. Какой язык для чего

| Задача | Чем делать |
|---|---|
| Экраны, логика интерфейса, данные пользователя | JavaScript (без сборщика, без npm-зависимостей, без CDN) в `features/<имя>/` |
| Вид, анимации, цвета | CSS в папке модуля; общие токены и базовые стили в `core/styles.css` |
| Доступ к Android: файлы, Intents, процессы, разрешения, буфер обмена, печать | Kotlin в `java/.../<имя>/` |
| HTTP к ИИ-провайдерам и поиску | Kotlin (OkHttp), ключ читается из Keystore и **не попадает в JS** |
| HTTP к Supabase (вход, синхронизация) | JavaScript `fetch`: публичный anon-ключ не секрет |
| База и права доступа | SQL в `features/<имя>/schema.sql`, владелец выполняет его в Supabase SQL Editor |

Не добавляй библиотеки и AndroidX без явной необходимости. Если нужна (например, Credential Manager для входа через Google), объясни владельцу зачем.

## 5. Как проверять (ты не можешь запустить приложение)

- JavaScript: `node --check файл.js` для каждого изменённого файла.
- Интерфейс: тесты в `docs/tests/` загружают `index.html` в jsdom, подменяют мост `window.KairemaBridge` и `fetch` и проходят сценарии
  (вход, синхронизация двух «телефонов», терминал и агент). Запуск: `cd docs/tests && npm i jsdom && UI_DIR=../../app/src/main/assets/ui/ node terminal.test.js`.
  Добавляй тест на каждую новую возможность. Подробности в `docs/tests/README.md`.
- Kotlin: проверь вручную: импорты, типы, `null`-безопасность, SAM-лямбды (пиши `Runnable { }` явно, чтобы не было неоднозначности перегрузок),
  `val`/`var`, возвраты из лямбд, версии API (minSdk 26), что `@JavascriptInterface` методы публичные и принимают простые типы.

## 6. Сборка и выкладка (как это работает у владельца)

1. Владелец открывает репозиторий на GitHub: Add file, Upload files, загружает `kairema.zip` в корень, Commit changes.
2. Workflow `.github/workflows/build.yml` находит .zip в последнем коммите, удаляет `app/` и `settings.gradle.kts`, распаковывает архив поверх, удаляет zip и коммитит результат
   от имени github-actions, потом собирает debug APK (JDK 17, Gradle 8.9, `assembleDebug`). Артефакт: `kairema-debug-apk`.
3. Владелец открывает Actions, нужный запуск, скачивает артефакт, ставит `app-debug.apk` поверх старого.
4. Если сборка красная, он присылает скриншот шага. Частые причины: ошибка Kotlin (импорт, тип), 403 при push (Settings, Actions, General, Workflow permissions: Read and write),
   «does not contain a Gradle build» (второй коммит без zip).

## 7. Безопасность (не обсуждается)

- API-ключ **никогда не попадает в JavaScript**, логи и промпты. JS передаёт только id провайдера, Kotlin берёт ключ из Keystore (`data/SecureKeys.kt`).
- Ключи поиска отправляются только на фиксированные адреса Tavily, Brave и Serper.
- Чужой текст (ответ модели, результаты поиска, файлы) выводится через `textContent` или `mdRender`, не через `innerHTML`. Ссылки только http(s).
- Команды терминала от ИИ выполняются **только после подтверждения владельца**. Опасные команды (удаление, системные пути) помечаются и в автоматическом режиме агента не запускаются.
- Геопозицию и подобные данные только с явного согласия пользователя.
- В репозиторий не попадают секреты. Исключение: `app/debug.keystore` (пароль `android`) нужен **только** для debug-сборок. Для релиза нужен другой, секретный ключ.
- Публичный anon-ключ Supabase безопасен только вместе с включённым RLS на таблицах. Секретный ключ Supabase (`sb_secret_`) никогда не вставляй в приложение.

## 8. Как не мешать друг другу (разделение ролей)

Работает один Claude над одной задачей. Перед стартом посмотри «Сейчас в работе» в `docs/NOTES.md`.

- **Роль «Ядро»:** логика, Kotlin, мост, синхронизация, терминал, архитектура, тесты. Меняет `.js`, `.kt`, `.sql`.
- **Роль «Дизайн»:** внешний вид. Меняет `.css`, разметку и тексты внутри шаблонных строк, анимации. **Не меняет логику.**
  Если для дизайна нужна логика, пишет просьбу в `docs/NOTES.md` для «Ядра».
- Общие файлы (`core/app.js`, `core/hooks.js`, `index.html`, `core/styles.css`) правятся **только точечно**, и такая правка записывается в `docs/NOTES.md`.
- Не удаляй и не переименовывай чужие модули без просьбы владельца. Не меняй формат данных без миграции.
- Спорные места (две версии одной функции) не решай молча: опиши в `docs/NOTES.md` и спроси владельца.

## 9. Частые ловушки (уже наступали)

- Старая база: zip собран от устаревшей копии репозитория и затёр чужую работу (правило 6).
- `startService` в Termux из фона: Android отвечает «app is in background». Решение: резерв `startForegroundService`.
- Разрешение `com.termux.permission.RUN_COMMAND` не видно в настройках на некоторых прошивках: запрашивать окном из приложения (`termuxRequestPermission`).
- Бесплатная почта Supabase шлёт ссылки, а не коды, и ограничена 2 письмами в час. Код на почту требует своей отправки писем (SMTP).
- Из папки данных приложения Android 10+ нельзя запускать файлы: программы запускаются только из Termux или из `lib/` внутри APK.
- WebView на Android не поддерживает `getDisplayMedia` (демонстрация экрана) и веб-распознавание речи: это делается нативно.
- `http://` адреса блокируются (cleartext отключён): локальный сервер без https не подключить.
- Тест `.opt`/селекторы ломаются после редизайна: тесты ищи по смыслу (`data-*`, текст), не по классам оформления.
