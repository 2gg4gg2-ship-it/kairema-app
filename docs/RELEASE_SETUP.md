# Подписанный release APK и тесты Kotlin: что сделать один раз

Что уже в проекте (в архиве): `app/build.gradle.kts` умеет собирать `release` с подписью из переменных окружения, сжатием кода библиотек и ресурсов (R8, правила в `app/proguard-rules.pro`);
тесты Kotlin лежат в `app/src/test` (Guard, тексты ошибок, правила обновления). Чтобы CI это использовал, нужны два ручных шага (папку `.github/` архив не трогает).

## Шаг 1. Положить ключ в секреты GitHub
Ключ создан отдельно и передан в чате файлом `kairema-release-secrets.txt` (там два значения). Репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**, создай два секрета:

| Имя секрета | Значение |
|---|---|
| `KAIREMA_KEYSTORE_B64` | длинная строка из файла (одна строка, без пробелов и переносов) |
| `KAIREMA_STORE_PASS` | пароль из файла |

Сам файл ключа и пароль сохрани в надёжном месте (облако, менеджер паролей). **Потеряешь ключ — новые версии нельзя будет поставить поверх установленной, придётся удалять приложение.** Не публикуй их и не клади в репозиторий.

## Шаг 2. Заменить `build.yml`
Открой `.github/workflows/build.yml` → карандаш → удали всё → вставь содержимое файла `docs/build.yml.example` из репозитория (он полный, вместе с шагом публикации релиза из `UPDATER_SETUP.md`; делать два раза не нужно) → **Commit changes**.

Что делает новый файл: запускает тесты Kotlin (не блокируют сборку), собирает debug как раньше, и если секреты есть, собирает подписанный release, кладёт APK в артефакты и в **Releases** (иначе в релиз попадёт debug).

## Первый переход на release (один раз)
Release подписан другим ключом, чем debug, поэтому Android не поставит его поверх текущей версии. Порядок:
1. В приложении сделай резервную копию (Настройки → Резервная копия) и сохрани файл вне приложения.
2. Удали приложение Kairema (данные в нём пропадут).
3. Установи release APK (из Releases, через обновление не получится), восстанови копию.
4. Дальше «Обновление» в приложении работает как раньше: новые release встают поверх.

## Что проверить после первой сборки
- Вкладка **Actions**: шаги «Kotlin unit tests» и «Build signed release APK» зелёные. Красный «Kotlin unit tests» не мешает, но пришли лог.
- В Releases есть `Kairema-<версия>.apk`; он должен быть меньше или такого же размера, как debug.
- Приложение запускается, работают чат, терминал, обновление, вибро. R8 мог что-то вырезать лишнее, на это нет теста в этой среде.

## Что не проверено
Сборка release и R8 не запускались (в этой среде нет Android SDK и доступа к Maven). Тесты Kotlin для `Guard`, `Texts`, `UpdateRules` были скомпилированы и прошли здесь отдельным компилятором (13 тестов). `Bridge.kt` целиком (WebView, сеть, потоки) тестами не покрыт, его проверяют только сборка и ручной запуск.
